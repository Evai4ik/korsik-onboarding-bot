# Развёртывание и проверка

1. Создайте собственного бота в MAX и получите новый токен.
2. В Make импортируйте `make/korsik.make.blueprint.sanitized.json`.
3. Создайте собственный Webhook MAX и свяжите его с модулем **Webhook 4**; настройте в MAX подписку на `message_created`.
4. Создайте Data Store `Korsik Conversations` и его поля: `conversation_id`, `first_name`, `last_name`, `department`, `position`, `start_date`, `mentor_name`, `adaptation_stage`, `completed_tasks`, `registration_step`, `user_id`, `profile_status`, `role`.
5. Перепривяжите **все** модули Data Store к новому хранилищу (ID в опубликованном Blueprint сброшены).
6. Подключите Dify и настройте приложение / его знания отдельно; перепривяжите подключения Dify и JSON-схемы ответов.
7. Во всех HTTP-модулях MAX замените значение заголовка Authorization на собственный токен. Для соединения с MAX API может потребоваться доверенный сертификат CA — настройте его в Make без отключения TLS-проверки.
8. Повторно создайте или выберите необходимые JSON body data structures (ID сброшены).
9. Сначала проверьте сценарий в `Run once`: обычное сообщение, главное меню, регистрацию, диалог Dify, HR-меню, списки и роли. Затем включите автоматическое выполнение.

## Ограничения

- Данный JSON — демонстрация логики, не готовый «импорт и запуск»: отсутствуют реальные внешние подключения, знания Dify, разрешения и секреты.
- Кнопки HR «Отчёты», «Напоминания», «База знаний» могут присутствовать без завершённой логики.
- Личные данные в MAX и Dify должны обрабатываться только при наличии правового основания и политики доступа.
- Не включайте `bot_started` в существующий обработчик без отдельной ветки: структура этого события отличается от `message_created`.
